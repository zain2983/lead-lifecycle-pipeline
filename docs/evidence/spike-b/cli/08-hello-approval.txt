# Sim workflow source: primer

`workflow.ts` is a Sim workflow as TypeScript; the server compiles it statically and nothing in it runs. Commands read the workflow id from `.sim/base.json`; run them from this directory.

**Edit loop**: edit `workflow.ts` (and `functions/*`) → `sim workflows source check --dir .` (offline; it also adds new blocks to `tsconfig.json`) → `bunx -p typescript@7.0.2 tsc -p .` → `sim workflows source apply --dir . --dry-run` → `--yes`. Rerun each step until it exits 0. Apply saves the draft in canonical form: read `workflow.ts` again before the next edit.

- **Deletes**: removing a block or a variable needs `apply --allow-delete` (`E_APPLY_BLOCK_DELETE` / `E_APPLY_VARIABLE_DELETE`).
- **Deploy**: apply saves a draft; `apply --deploy` also deploys it, or `sim workflows deploy <workflowId>` publishes the saved draft later.
- **Identity**: a block is its entry in `.sim/lock.json`, which binds it by its const name or its display name. Change the display name (first argument) freely: references through the const follow it, and the apply rewrites every `$ref.<old key>` and `<old key.…>` to the new key and reprints the files (don't hand-edit them). Renaming the const too keeps it when settings, neighbours or references still tie it to the old block; otherwise the apply refuses a delete (`E_APPLY_BLOCK_DELETE`). Safest: keep the const.
- **References**: in `workflow.ts` read an output as `x.content`, a loop or parallel item as `p.currentItem` (`p.index`), text as `` t`…` ``, env as `env.NAME`. In a function code file (`codeFile('./functions/x.js')`) read an output as `$ref.<key>.<path>`, the key being the display name lowercased, whitespace and dots removed ("Triage Agent" → `$ref.triageagent.content`); in a loop body `$ref.loop.currentItem` / `$ref.loop.index`, in a parallel `$ref.parallel.currentItem` / `$ref.parallel.index`; env as `$env.NAME`. In `.py`/`.sh` files write `<key.path>` and `{{NAME}}`, not `$ref`/`$env`. Read an index or item only inside its container (`E_APPLY_REF_OUT_OF_SCOPE`), after it its `.results`. A `$ref` naming no block is an error in a function file you edited (`E_APPLY_UNRESOLVED_REF`).
- **Renames**: one variable per apply (two at once read as a delete and an add).
- **Look up a builder**: `sim workflows source params <builder>` (`agent`, `trigger.schedule`; a namespace like `gmail` lists its builders), offline.
- **Credentials**: `sim credentials connect <provider> --name "<Name>"`, give the owner its link, then `credential('<key>')` (`sim workflows source resources`).
- **Failures**: `x.onError(y)` runs `y` when `x` fails, reading the message as `x.error`. A retry is block meta, the third argument: `agent('Name', {…}, { retry: { enabled: true, maxTries: 3, waitBetweenTriesMs: 2000 } })`. Branches that each reply: a `response` per branch.
- **Run and debug**: `sim workflows run <workflowId> --manual --input '{…}'` runs the saved draft, no deploy needed (without `--manual` it runs the deployed version). Runs write real data (rows, emails): test on test resources. With `--dir <the workflow's folder>`, a failed run names the file and line that failed; then `sim logs get <runId> --trace --no-include-workflow-state` (spans hold resolved inputs).
- **Exit codes**: 0 ok, 1 errors, 5 stale (`sim workflows source get --dir <fresh dir>`, redo the edit there), 9 rate limited, 10 busy, 11/12 `status`: your edits / the server changed. Every code: `.sim/AGENTS.md`.

## Builders this source uses

- `trigger.start` (Start): `const x = trigger.start('Name', {})`
  optional: inputFormat, runMetadata
  outputs: input, conversationId, files
- `response` (Response): `const x = response('Name', {})`
  dataMode (default "structured") picks the rest: "structured"; "json"
  optional: status, headers
  outputs: data, status, headers
